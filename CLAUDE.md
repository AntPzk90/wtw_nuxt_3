## Commands

npm is the package manager (`package-lock.json` is committed).

- `npm install`: install deps; `postinstall` runs `nuxt prepare`, which regenerates `.nuxt/` (types and tsconfigs)
- `npm run dev`: dev server at http://localhost:3000
- `npm run build`: production build into `.output/`
- `npm run preview`: serve the production build locally
- `npm run generate`: static prerender
- `npm run mock`: mock WTW API at http://localhost:3001 (port via `API_PORT`)
- `npm run lint`: ESLint + Stylelint + Prettier check (`lint:js`, `lint:style`, `format:check` run them one by one)
- `npm run lint:fix` / `npm run format`: auto-fix everything / only reformat
- Single file: `npx eslint path`, `npx stylelint path`, `npx prettier --check path`
- `npx nuxi typecheck`: type-check (needs `vue-tsc` and `typescript` installed as dev deps first)

## Architecture notes

- **Nuxt 4 directory layout**: application source lives under `app/` (`app/app.vue`, and later `app/pages/`, `app/components/`, `app/composables/`, `app/layouts/`, etc.). `server/`, `public/`, and `nuxt.config.ts` stay at the repo root. Don't create `pages/` or `components/` at the root; Nuxt 4 won't pick them up.
- **Auto-imports**: Vue APIs, Nuxt composables, and anything in `app/components/`, `app/composables/`, and `app/utils/` are auto-imported. Don't add explicit imports for them.
- **Components**: `nuxt.config.ts` sets `pathPrefix: false`, so subfolders (`layout/`, `movie/`, `catalog/`, `forms/`, `player/`) only group files and a component's name is its file name (`movie/MovieTabs.vue` → `<MovieTabs>`). File names must stay unique across folders. BEM modifiers that depend on context (`movie-card__head`, `movie-card__poster--big`, ...) are passed as `class` from the parent and fall through to the root element.
- **Styles and icons**: the whole markup stylesheet is loaded globally from `app/assets/css/main.css`, and components use its BEM classes without scoped styles. Icons are `<symbol>`s in `app/components/SvgSprite.vue` (rendered once in `app.vue`) and are used as `<svg><use href="#id" /></svg>`. `public/img/` holds the markup images for the static templates; once data comes from the API it's only needed for things like the player poster.
- **Routing**: there's no `app/pages/` directory yet, so `vue-router` isn't active. Creating `app/pages/` turns on file-based routing; `app/app.vue` must then render `<NuxtPage />`.
- **TypeScript**: the root `tsconfig.json` only references the generated configs in `.nuxt/`. If types look stale or missing, run `npx nuxt prepare` and don't edit the generated files.
- **Static markup**: `markup/` holds the original HTML/CSS mockups (BEM classes, `css/main.css`) that the Vue components are built from. Several files are states of one page (`movie-page-details`, `sign-in-error`, `player-pause`, ...).
- **API helpers** (`app/composables/useApi.ts`): both add `baseURL` and the `X-Token` header from the token cookie. `useApiFetch` (built with `createUseFetch`) is for page data in setup: it runs on the server and hands the result to the client in the payload, and refetches when the token changes. `apiFetch` is a plain `$fetch` for actions (clicks, submits, store actions). Don't call `useFetch` with `baseURL` directly, or requests go out without the token and `isFavorite` is always `false`.
- **Mock API** (`mock-server/server.mjs` + `mock-server/db.json`): a standalone Node server, not Nitro. It runs separately from `nuxt dev`. Custom handlers implement the htmlacademy WTW endpoints: `/films`, `/films/:id`, `/films/:id/similar`, `/promo`, `/favorite`, `POST /favorite/:id/:0|1`, `/comments/:id`, `/login`, `/logout`. Unmatched requests fall through to json-server, which also serves images from `mock-server/static/`. Auth is the `X-Token` header (base64 of the email); any email and non-empty password logs in. Posters (and all images of films without local stills) are external Wikimedia URLs, while other images are paths relative to `mock-server/static/` that responses turn into absolute URLs. Review ratings are 1–5 stars, matching the add-review form; a film's own `rating` stays on a 10-point scale. `isFavorite` is computed per user from `favorites`. POST requests write to `db.json`.
- **Lint setup**: ESLint uses the flat config generated by the `@nuxt/eslint` module (`eslint.config.mjs` wraps `.nuxt/eslint.config.mjs`, so run `nuxt prepare` first on a fresh clone) with `eslint-config-prettier` last. Prettier owns formatting (no semicolons, single quotes, width 100). Stylelint extends `stylelint-config-standard`, parses `.vue` through `postcss-html`, and enforces BEM class names. `app/assets/css/main.css` is the built markup stylesheet and is excluded from Stylelint and Prettier on purpose.
- `nuxt.config.ts` pins `compatibilityDate: '2025-07-15'` and turns on Nuxt DevTools with `disableAuthorization: true`, so its locked tabs (terminals, server routes, file editing, ...) open without the one-time link from the terminal.
